開発背景

04 Background

Background

背景

  • ファッション・趣味・家電など日本商品を求める人が着実に増えている
  • 海外直接購入への関心は高いが、初めて試すにはハードルが高い

Problem

課題

  • 韓国への直送に対応していない日本のショッピングサイトが多い
  • 日本語サイト・決済手段・配送規定が分かりにくい
  • 注文した商品が今どこにあるか分かりにくく、問い合わせ先も少ない

Solution

解決

  • 注文書1枚で購買代行・配送代行を申請
  • 韓国語・日本語・英語の画面切替
  • 注文進行5段階の確認と入庫・出庫の通知メッセージ
  • お知らせ・1:1掲示板・FAQですぐに問い合わせ

Goal

誰でも簡単に日本商品を購入し、安全に受け取れるサービス・学んだJava Web技術(Servlet / JSP / Oracle)を一つのサービスに統合

Technology

技術スタック

06 Tech Stack

Backend

Servlet・JSPベースのWebアプリケーション。Tomcat 9で動作し、JSPはスクリプトレット方式で作成しました。

Java 17Servlet 4.0JSP 2.3Tomcat 9

Database

Oracle DBにJDBCで接続します。共通接続ユーティリティ(DBmanager)とDAO層でクエリを分離しました。

OracleJDBC (ojdbc8)DAOSequence

Architecture

Controller(Servlet) → Command → DAO で責務を分けたMVC構造。パートごとにコードを分離して協業しました。

MVCCommand PatternDTO

Security

パスワードはBCryptで暗号化し、フィルタで偽造リクエスト・未ログインアクセス・管理者アクセスを防ぎます。

BCryptCsrfFilterAuthFilterAdminFilter

Multi-language

GTranslateウィジェットで韓国語・日本語・英語を切り替え、言語別のバナー画像を自動で入れ替えます。

KO / JA / ENGTranslateBanner Swap

Frontend & Tools

フレームワークを使わず、純粋なHTML・CSS・JavaScriptで画面を作りました。為替レートは外部APIで1日1回更新します。

HTML / CSS / JSEclipseVS CodeSQL Developer

Part 02

購買代行 / 商品登録 ソン・ヒョンソプ

13 Part 02

購買代行・商品登録

  • 注文書の登録 (受付待ち → 受付申請)

    受付待ちは一時保存・受付申請は住所・携帯電話・追跡番号・規定への同意後に修正不可

  • 商品の登録

    1つの注文書に複数の商品・画像アップロード (5MB以下 JPG・PNG・GIF・WEBP)

  • 購買代行・配送代行の共通構造

    同じコード・同じテーブルを使い、URL(/buyorder, /shiporder)で区別

  • 注文一覧・詳細・削除

    マイ注文を10件ずつ表示・受付待ちの注文のみ修正 / 削除

為替・決済・進行状態

  • 為替レートの自動更新

    サーバーが1日1回外部APIから為替レートを取得し、EXCHANGE_RATEに保存

  • ウォン決済予定額

    保存時点の公示為替レートで計算 → 受付申請すると決済管理の待機件として登録

  • 注文進行5段階

    申請完了 → 入庫 → 送料待ち → 出庫 → 国内配送中

  • 管理者処理・通知

    入庫・決済確認・出庫処理時に会員へ通知メッセージを送信

@WebServlet({"/buyorder/*", "/shiporder/*"}) BuyOrderController → BuyOrder* Command → BuyOrderDAO (注文+商品は1トランザクション)
